Source Watch, rebuilt as one pipeline

Today the page has nine tabs in no particular order. This plan lines them up as five stages, from funder websites on the left to published catalog calls on the right. It also adds a way to pick websites straight from the 10,049 calls and 1,813 funders already in the database. No code has changed yet.

3 · Import from the funding database

How an admin picks websites to watch

The admin searches the database rather than typing URLs. Results are grouped by website, because Source Watch watches a website's listing page, not a single call. One row such as grants.nih.gov stands for all 249 NIH calls behind it.

For each website the admin sees who funds through it, how many calls the database holds there, how many are still open, and whether it is already watched. A warning appears where watching would not work, for example a file store like cdn.pfizer.com, or a page that needs a browser to render.

Picking a row opens a short setup form. Most of it is filled in from the database, so the admin mostly confirms and approves.

  1. Search by funder, programme, country or website, with filters for funder type, call status, and "not yet watched".
  2. Pick websites. Each result suggests a listing page to watch, worked out from the call URLs (for example /grants/guide/ rather than one PDF).
  3. Confirm the setup: which page to watch, the funder link, that it is the official website, how often to check, and the priority.
  4. Add to the pipeline. The websites go to Sources as approved and get their first check. Nothing reaches the catalog without passing Review.

Two data problems the form has to catch. www.dfg.de has calls linked to India's DST, so the funder link needs a human check. The existing "Suggest sites from catalog" button reads 500 calls at a time in database order, with no search, which is why this plan replaces it.

6 · Build scope

What gets built

  1. Page layout: the five-stage bar with live counts, existing tab components moved into their stages, Quality and Settings at the top right. The page opens on the first stage that needs attention.
  2. Search endpoint: one read-only query that groups calls by website and returns funders, call counts, open counts, a suggested page to watch and an "already watched" flag. It needs no schema change.
  3. Import panel and setup form under Sources, with the fields above and a preview check before adding.
  4. Save the confirmed website on the funder (funders.website_url), so the database improves each time an admin adds a site.
